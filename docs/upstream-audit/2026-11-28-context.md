## 取舍规则

- 仅同步已有功能的安全修复、缺陷修复和性能改进；混合提交只取保留功能所需的 hunk。
- 不引入新功能、新功能依赖、已删除模块、配置开关或兼容层。
- 历史 Alembic 迁移保持原样，head 仍为 `d4c1a8e37b62`（58 个 revision）。
- SQLite 默认安装、可选 extras、单进程运行和延迟导入策略保持不变；不新增运行时依赖。
- 前端沿用 Pure 的 `--color-gray-*` 令牌，不引入上游的 `base-*` 色阶。
- 翻译目录由 `npm run i18n:parse` 生成（CI 要求工作树干净）；只随所选修复补必要键，不手抄上游目录。
- **用户自有 UI 区域不动**：`SettingsModal`/`UserMenu`/`Connections/Connection.svelte` 的管理员入口是用户特意整合的左下角设置（`1292a4a4d`）。任何提交若只为这一区域新增交互，一律 skip；若确实触及这些文件，先经用户确认。
- 同步不包含生产部署或远端发布；验证门禁为 GitHub Actions（Backend CI / Frontend Build / Pure container regression / Pure Image）。

## 判定方法

按文件路径把每个提交归入 7 个 scope（`backend-db`、`backend-api`、`backend-runtime`、`frontend-chat`、`frontend-ui`、`frontend-management`、`infra-i18n`），逐 scope 判定后落到 6 类决定：

| 决定               | 含义                                                       |
| ------------------ | ---------------------------------------------------------- |
| `adopt`            | 保留路径上的修复，按上游形态移植                           |
| `adapt`            | 混合提交，只取保留功能所需 hunk                            |
| `already-covered`  | Pure 已具备等价实现或从未引入上游的问题代码                |
| `skip-removed`     | 修复对象属于已删除功能                                     |
| `skip-new-feature` | 属于新功能或新交互，不属缺陷/安全/性能修复                 |
| `skip-engineering` | 纯视觉、代码分割、翻译目录等无行为变更                     |

聚合脚本校验：每条记录恰好出现一次、`id` 连续、`groups` 与 `decisions` 一一对应、`applied` 中的每条都有对应的 `applied` 记录，`coverage_errors = []`。
